# 测试覆盖与仿真审计

## 结论

项目原有测试不能视为“覆盖全部功能、完全仿真”：它有较好的后端回归基础，但缺少可执行的 API 全量清单、覆盖率门槛、真实 HTTP 客户端测试和真实浏览器课堂流程。当前测试体系已补为两层：

- 快速回归层：150 个用例，覆盖全部 53 个业务 API 路由清单、主要服务、异常分支、持久化、并发和分发契约；按语句与分支综合计算的后端覆盖率为 86.10%，CI 门槛为 85%。
- 浏览器 E2E 层：1 个完整课堂场景，使用真实 Chromium、真实 Uvicorn、真实 SQLite、真实 SSE 和本机假模型供应商，贯通教师登录、开始课堂、学生加入、流式回答、课堂记录和结束后撤销旧链接。

“完全仿真”仍不能等同于“所有生产环境都已验证”。外部模型供应商的真实限流/计费/故障语义、真实局域网、多台学生设备、iPad Safari、打包后的 EXE、Windows DPAPI 跨电脑迁移，以及 30 分钟以上压力稳定性仍属于发布前真机验收范围。

## 运行快速回归和覆盖率门槛

从仓库根目录运行：

```powershell
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r backend\requirements-dev.txt
python -m pytest -q -p no:cacheprovider -m "not e2e" --basetemp=.pytest-tmp --cov=backend/app --cov-branch --cov-report=term --cov-fail-under=85
python -m compileall -q backend/app desktop
```

覆盖率是防退化门槛，不代表每一行都具有同等业务价值。新增路由时，`test_route_inventory_openapi_and_root_redirect_are_complete` 会要求同步更新 API 清单；新增高风险分支时应补行为断言，而不是只追求数字。

## 运行真实浏览器课堂仿真

首次运行先安装测试浏览器：

```powershell
python -m playwright install chromium
```

然后运行 E2E：

```powershell
$env:RUN_BROWSER_E2E = "1"
python -m pytest -q -p no:cacheprovider -c pytest.ini -m e2e --basetemp=.pytest-e2e-tmp
```

E2E 测试会自行启动两个仅绑定 `127.0.0.1` 的临时服务：一个 EduGate 实例和一个 OpenAI-compatible 假供应商。测试数据写入逐用例临时目录，结束后关闭服务，不使用真实 API Key，也不访问真实模型。

## 发布前人工验收

1. 在干净的 64 位 Windows 电脑上构建并运行完整便携目录，而不是只复制 EXE。
2. 用教师电脑和至少两台局域网学生设备完成开始课堂、流式提问、换链和结束课堂。
3. 用 iPad Safari 检查横竖屏、触控目标、标签页和输入法。
4. 接入计划使用的每一家真实模型供应商，验证模型发现、超时、429、5xx、SSE 和费用控制。
5. 停止服务后执行备份；修改配置和知识库；恢复并重启，核对数据回滚。
6. 用目标班级规模执行至少 30 分钟压力测试，观察 429、首字延迟、内存、SQLite 等待和上游并发。
